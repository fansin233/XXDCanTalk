# 会说话的西小电：产品与游戏设计方案

版本：规划 v1.0 · 日期：2026-09-29 · 引擎基线：Godot 4.6.1

本方案面向实际开发者、技术美术和执行模型。建议把“自然的模仿互动、可读的角色表演、轻量的陪伴成长”做成首版的三个支点。核心体验全部在手机本地完成。

阅读顺序：本文 → [技术架构与语音规格](TECHNICAL_SPEC.md) → [开发任务与验收](IMPLEMENTATION_PLAN.md)。模型检查原始数据见 [model_audit.json](model_audit.json)。

下一阶段的商店、背包和独立出行以 [商店、背包与出行开发规格](SHOP_INVENTORY_TRAVEL_SPEC.md) 为准。该文档基于 1.0.1 的实际代码，包含数值表、存档迁移、离线结算和实施验收；这些扩展功能目前属于待开发方案。

本文中的“已检查”来自本项目；“目标”和“初值”是拟定的设计要求；真机性能、语音效果和玩家感受仍需按验收计划验证。它们不是已经达成的结果。

## 1. 当前项目的真实起点

实际 Godot 根目录为：

~~~text
E:/作品/XXD/XXDCanTalk/会说话的西小电/
~~~

资源目录现有拼写为 **Assests**。开发时必须使用真实路径，不能凭描述写成 Assets、assest 等其他拼写。

| 已检查项目 | 结果 | 对开发的影响 |
|---|---|---|
| 引擎 | 4.6.1.stable.official.14d19694e | 首轮实现与导出模板使用匹配版本 |
| 开工时项目内容 | 初始 MCP 检查到 0 个场景、0 个脚本；无主场景设置 | 基础结构现已建立；当前状态见 [BUILD_STATUS.md](BUILD_STATUS.md) |
| 渲染 | Compatibility；Windows 使用 OpenGL，移动设备使用 OpenGL ES 3.0 | 以较广的旧设备覆盖为默认目标，仍需在目标手机验收帧率和画质 |
| 当前运行时角色 | res://Assests/Model/xxd2.gltf；旧 `XXD.glb` 和 FBX 保留作参考 | glTF 的材质贴图已在 Godot 主场景画面核对正确 |
| glTF 导入网格 | 1 个 MeshInstance3D、4 个 surface；12,045 个顶点、17,422 个三角面 | 面数处于中档目标附近；仍需在低端机检查帧率和内存 |
| glTF 骨架与蒙皮 | 有 Skeleton3D，88 根骨骼；网格有 88 个 Skin bind 及顶点骨骼权重；包含头、颈、上身、手臂、腿骨 | Godot 桌面主场景中已用程序姿势观察到蒙皮随骨骼变化；正式动画仍需制作 |
| glTF 动作与面部形变 | 没有动画片段，也没有 blend shape；角色当前以程序骨骼旋转表现待机、倾听等原型动作 | 正式动作片段、眨眼和发声表现仍需制作 |
| glTF 材质贴图 | 4 个材质引用头部、身体、红色部件、腰带贴图；头/身各 1024²，腰带 4096²，红色贴图 1² | 主场景已核对贴图显示；腰带导入尺寸限制为 2048 并使用 VRAM 压缩与 mipmap，真机需复核画质和格式 |
| 旧 FBX 导入结果 | 1 个静态 MeshInstance3D、1 个 surface；134,660 个顶点、226,696 个三角面；无骨骼 | 保留为对照或源资产；不再作为当前可表演角色依据 |
| 旧相邻贴图 | res://Assests/Model/xxd.png，4096×4096；旧 FBX 导入材质未绑定该贴图 | 不作为当前 glTF 的贴图；新模型使用其自身导出的材质贴图 |
| 其他资源 | 有 BGM、音效、图片、另一个小型 GLB | 逐项试听/预览后选用，文件存在不代表适合当前玩法 |

旧 FBX 的静态网格结论不适用于 `xxd2.gltf`。主场景现以新 glTF 为角色，材质显示和程序骨骼姿势已在 Godot 桌面预览核对；肩部旋转让角色离开原始 T pose。原模型无动画片段和面部 blend shape，因此现有姿势只构成动作原型，不能代替正式动画、眨眼与发声表情交付。移动设备上的蒙皮开销和画质仍未验收。

网格包围盒约为 0.872 × 1.185 × 0.708 个引擎单位，底部目前不在 y=0；这不是已确认的人体尺寸。模型产出时统一比例、朝向和脚底原点，避免代码散落补偿缩放。

## 2. 产品定位与首版边界

默认设计假设：竖屏、单角色、单房间、单人、离线可玩、中文界面；Android 优先交付，iOS 使用相同游戏逻辑并独立验证平台层。受众按轻度休闲玩家设计，具体年龄定位及发行渠道在发布阶段冻结。

一句话体验：**你开口，西小电认真侧耳听，再用滑稽的高音模仿；你陪它玩和照顾它，它会学会更多表演，并让房间越来越有你的风格。**

| 范围 | 内容 | 达成标准 |
|---|---|---|
| P0：可玩的核心样片 | 主角显示、待机、点击反馈、自动收音与按住说话、侧耳、高音复述、声音开关、权限处理 | 玩家在手机上完成一次完整模仿互动 |
| P1：首个完整版本 | 三项状态、亲密成长、喂食/休息/抚摸、一个小游戏、装扮、任务、保存、质量档位 | 形成 3–8 分钟的自洽游玩循环 |
| P2：有验证结果再扩展 | 更多房间与小游戏、更多声音风格、明确由玩家发起的录屏分享、节日内容 | 核心留存和性能稳定后逐项评估 |
| 独立立项功能 | 理解语言的 AI 对话、云同步、账号、联网排名、付费与广告 | 分别评估服务、成本、隐私与平台工作量 |

“复述”定义为播放玩家刚才的声音并改变音高，保留口音、笑声和情绪。首版不依赖语音转文字，也不要求角色理解句子含义。任务和反馈只能依赖实际可检测的声音、触摸及游戏事件。

## 3. 让游戏有趣的三个循环

| 时间尺度 | 玩家做什么 | 立即反馈 | 再玩一次的理由 |
|---|---|---|---|
| 5–20 秒 | 说话、做声音、点角色 | 侧耳、模仿、表情、轻微喜剧动作 | 同一互动有少量变化，玩家能主动逗角色 |
| 3–8 分钟 | 照顾角色、玩一局跑酷、换装 | 状态恢复、获得小电星、解锁动作或装饰 | 看得见的小目标与创作空间 |
| 数天 | 尝试不同互动，完成轻量目标 | 新待机、新表情、新房间小物 | 角色表现越来越丰富，形成陪伴感 |

趣味优先来自表演和响应速度。基础待机要有视线、重心与手部小动作；动作变体使用带冷却的加权随机，避免同一特殊动作连续出现。倾听时把注意力集中到玩家，复述时根据音量起伏带动面部或发声部件。

成长奖励扩展角色的表现，不提高复述音质、不限制麦克风使用，也不要求玩家刷资源才能进行核心互动。

### 3.1 第一次打开的体验

| 阶段 | 玩家体验 | 实现约束 |
|---|---|---|
| 进入房间 | 西小电挥手，一句“点点我试试” | 首屏即可触摸；设置与静音入口始终可见 |
| 第一次触摸 | 摸头后眯眼或开心，建立“它会回应我”的预期 | 此时即可体验，无需麦克风权限 |
| 点麦克风 | 显示一句用途说明，随后申请系统权限 | 用户明确开启后才进入收音流程 |
| 第一次说话 | 音量指示变化，西小电侧耳 | 保留句首，屏幕显示“我在听” |
| 第一次复述 | 高音模仿完成，西小电做一个得意小动作 | 游戏自身声音不会再次被录入 |
| 第一次奖励 | 获得一件引导装饰，并提示喂食或小游戏 | 1–2 分钟内看到成长空间 |

拒绝麦克风后仍能继续抚摸、照顾、小游戏和换装。设置页提供再次开启说明，不循环弹出系统授权。

### 3.2 主界面布局

设计逻辑尺寸为 720×1280；使用锚点、容器和安全区域适配实际屏幕。

~~~text
顶部安全区
┌──────────────────────────────────────┐
│ 昵称 / 亲密等级                设置   │
│ 饱腹       电量       心情            │
│                                      │
│            西小电                    │
│        可点击的头 / 身体 / 脚          │
│                                      │
│       状态气泡：我在听 / 正在模仿      │
│                                      │
│    喂食    玩耍    休息    装扮       │
│            麦克风 / 按住说话          │
└──────────────────────────────────────┘
底部安全区
~~~

角色占据可用画面的主体，控件避开头部和主要动作范围。实际交互尺寸以设备上的可触达性验证；按 Android 约 48dp、iOS 约 44pt 设计触摸热区，不把 44 个游戏坐标像素直接当成同等物理尺寸。

气泡表达当前行为，不显示调试术语。声音阈值、帧率、缓冲等信息只放开发面板。嘈杂时用“这里有点吵，可以按住和我说话”引导手动模式。

## 4. 核心语音玩法

用户可以开启自动模仿，也可以按住麦克风按钮说话。自动模式在声级连续超过门槛后进入倾听，句尾安静一小段时间后复述。手动模式由按下/松开划分句子，适合嘈杂环境。

~~~mermaid
flowchart LR
    A[待机并等待声音] --> B[声级连续过阈值]
    B --> C[侧耳倾听并保留录音]
    C --> D[句尾停顿或松开按钮]
    D --> E[整理音频并高音复述]
    E --> F[短暂冷却]
    F --> A
~~~

首版使用本地音频回放。推荐声音初值为原音高/语速的 1.30 倍，可在调试中比较 1.20–1.40；这个方案会同时加快说话。若后续要求“只升调、保持语速”，另使用变调效果器并测量低端机的音质和开销。[Godot 播放器说明](https://docs.godotengine.org/en/4.6/classes/class_audiostreamplayer.html#class-audiostreamplayer-property-pitch-scale)

| 交互细节 | 设计要求 |
|---|---|
| 句首 | 提前缓存约 250ms，避免“你好”只录到“好” |
| 起听 | 过滤短促噪声；检测成立后先立即显示反馈，再完成侧耳动作 |
| 句尾 | 约 800ms 安静后判定结束；最终回放只保留少量自然尾音 |
| 长句 | 单段上限 12 秒；达到上限后停止本段，明确提示并复述已录部分 |
| 回放 | 一次只播放一段；角色表演跟随音频实际进度 |
| 防自我复述 | 回放期间关闭触发检测，丢弃麦克风输入，声学尾音消退后再开启 |
| 游戏声音 | 自动收音期间暂停 BGM；角色音效播放时临时让出收音权 |
| 临时中断 | 关麦克风、切后台、进小游戏、权限被撤销时取消当前会话 |
| 声音用途 | 默认只保留当前会话所需内存，结束/取消后释放；不上传录音 |

音量过阈值只能判断“出现了较明显的声音”，无法可靠区分玩家讲话、电视、人群或音乐。自动模式需要灵敏度调节、噪声校准和手动模式作为配套。详细状态、参数、采样与异常处理以技术规格为准。

## 5. 角色交互与养成

### 5.1 可直接感受到的互动

| 操作 | 首版反馈 | 节奏约束 |
|---|---|---|
| 点头部 | 抬头看玩家，短促惊讶或微笑 | 连点不无限叠加动画 |
| 在头部轻划 | 眯眼、身体轻靠近 | 同一次手势只结算一次抚摸 |
| 点身体 | 轻晃或痒痒动作 | 连续反馈有上限，避免一直锁住角色 |
| 点脚部 | 抬脚、侧看或小步退让 | 采用简洁反馈，保持角色在镜头范围 |
| 拖食物到喂食区 | 看向食物、吃下、满足 | 食物只消费一次，取消拖拽不扣资源 |
| 开始休息 | 打哈欠并进入休息姿态 | 任意时刻可唤醒；唤醒后恢复互动 |
| 复述结束 | 得意、点头或小小庆祝 | 低频变体；下一句优先于长庆祝 |

实时反馈允许重复；资源奖励需要冷却与上限。让玩家能一直逗角色，但不会因为点得快就破坏成长速度。

### 5.2 三项状态与亲密度

全部状态存储为 0–100。以下是第一轮平衡初值，不是最终数值。

| 状态 | 活跃时变化 | 主要恢复方式 | 低值表现 |
|---|---|---|---|
| 饱腹 | 每分钟 -0.15 | 基础能量饼干 +25，冷却 30 秒 | 摸肚子、望向食物 |
| 电量 | 非休息时每分钟 -0.20；完成小游戏 -5 | 休息每分钟 +20 | 慢一点的待机、打哈欠 |
| 心情 | 每分钟 -0.10 | 抚摸 +4（10 秒冷却）；复述 +2（20 秒冷却）；小游戏 +10 | 需要陪伴的姿态 |
| 亲密经验 | 不衰减 | 当天前 5 次有效复述各 +4；前 3 次照顾各 +5；前 3 局小游戏各 +8；任务奖励 | 永久保留成长 |

离线衰减单独设为每小时：饱腹 -3、电量 -2、心情 -2，最多结算 8 小时；原先高于 20 的状态最多衰减到 20，原先已经低于 20 的状态保持原值，避免通过切后台获得免费恢复。离线期间处于休息状态时电量改为每分钟 +20，上限 100；达到充分休息后回到普通待机。切前后台的边界只结算一次，具体时间模型见技术规格。

所有照顾方式都有免费的基础入口。低状态改变角色演出和建议，不阻止复述、小游戏，也不造成死亡、装饰丢失或连续登录惩罚。

每级所需新增经验的初值为 60 + 20 × (当前等级 - 1)，先制作 10 级内容；每级有明确表演或外观奖励。首版先把 1–5 级填充完整，再扩展等级，避免只有经验条没有新内容。

### 5.3 货币与奖励节奏

唯一货币为“小电星”，用于房间小物与装扮。首版不再增加第二种付费货币或体力门票。

| 来源/用途 | 初值 | 目的 |
|---|---|---|
| 引导奖励 | 免费获得一件小装饰 | 第一次游玩即能尝试个性化 |
| 每日任务 | 每个 +5 小电星、+8 亲密经验；每天 3 个 | 提供方向，不能成为重复领奖漏洞 |
| 小游戏 | 每局 5–20 小电星 | 给主动玩法稳定产出 |
| 常见装扮 | 20–40 小电星 | 约 1–3 次短会话可购得 |
| 较稀有装扮 | 80–120 小电星 | 提供一周内可见的中期目标 |
| 状态照顾 | 基础喂食、休息、抚摸免费 | 玩家资源耗尽后依然能继续玩 |

这些价格要通过完整会话验证。首件额外可购装扮的目标是首日 5–10 分钟可获得，不能只凭表格推定节奏成立。同一解锁、任务、小游戏结算都必须有唯一凭据，重复回调不能发两次奖励。

### 5.4 任务与“有记忆”的表现

每日从小型任务池选 3 项，例如“完成 3 次模仿”“抚摸 3 次”“接到 10 颗电星”。所有任务用游戏事件计数，不要求识别玩家说出的具体词语。

记录上一次欢迎动作、近期两次反应与最近使用装饰，避免机械重复。可根据本地时段播放早安/晚间姿态；根据互动种类决定偏爱的待机变体。这里的“记忆”是少量本地状态和规则，可明确调试。

随机小事件每 2–4 分钟最多触发一次，仅在空闲时执行，例如观察房间摆件、试戴装饰、伸懒腰。声音、照顾与玩家主动操作的优先级更高。

## 6. 首版小游戏：西小电冲刺

采用纵向手机界面里的横向 2D 无尽跑酷。西小电自动向前跑，玩家点击跑道或“跳跃”按钮躲避路障，也可在桌面按空格、上方向键或 W。角色只能在落地后再次跳跃；规则简单，触控目标大。

| 要素 | 首版规则 |
|---|---|
| 时长 | 不限时；撞到路障结束当前一局，可重开或回家结算 |
| 控制 | 点跑道/跳跃按钮/空格/上方向键/W 单跳；退出按钮可随时返回 |
| 得分 | 每前进 10 个跑道单位得 1 分；电星 +25 分；能量电池 +60 分 |
| 难度 | 初速 300、每秒增加 5、上限 520；障碍高度与出现间隔随机变化，需给出可反应距离 |
| 判定 | 使用简单矩形碰撞，视觉边缘留有余量；跑道、角色和道具都裁切在场地内 |
| 结算 | 小电星 = clamp(1 + floor(本局得分 / 300), 1, 5)；完成后心情 +8、电量 -5 |
| 最佳成绩 | 在 `user://runner_best.cfg` 本地保存最高分，不上传或联网排名 |
| 提前退出 | 不结算奖励；重新开始或结算回家时一局只发一次奖励 |
| 语音 | 进入前暂时暂停自动收音；离开后按原有启用状态恢复 |

前 3 局每天提供亲密经验和小电星奖励上限；以后仍可玩并刷新本地最佳分数。跑道、角色、障碍和道具由轻量 2D 绘制，不依赖额外贴图；小游戏打开时不再显示房间主界面的交互按钮。

若前期实测玩家更喜欢声音互动，第二个玩法可做“节奏模仿”，但必须建立在收音延迟和噪声检测已经达标的基础上。

## 7. 美术与动画制作清单

### 7.1 角色资产先过关

首项技术美术工作是把现有资源变成可表演的手机角色。流程：

1. 已在 Godot 主场景中检查程序骨骼姿势和材质显示；后续在 DCC 工具核对 `xxd2.gltf` 的权重、原点、UV 与贴图源，并在目标手机复核。
2. 以现有形象为准优化 glTF 网格；当前约 17,422 三角面，作为中档起点，保留面部轮廓并减少不可见细节。
3. 确认权重与绑定正确后，识别 88 根骨骼中的变形骨骼及辅助骨骼；为手机版本精简无用骨骼，目标不超过 48 根变形骨骼、每顶点不超过 4 个权重。制作 8,000–15,000 三角面的低档模型。
4. 当前 glTF 材质已引用自己的头部、身体、红色部件和腰带贴图；腰带贴图导入上限设为 2048。基于手机验收结果再制作更低档资源，不要把旧的 xxd.png 强行覆盖到新模型 UV。
5. 利用已有头颈、上身、手臂和腿骨制作正式待机、侧耳、复述、触摸反馈等动画片段；没有 blend shape，需另选眨眼与嘴部表现方案。
6. 统一原点、比例、正面方向和装饰挂点，输出优化后的手机资产及稳定的动作映射清单。
7. 在 Godot 创建包装场景，通过 AnimationTree 调用动画，在实际手机上检查动作穿插、帧时间和蒙皮开销。

工作源文件放在工程外的 source_art 目录；保留原始 FBX，制作派生的 xixiaodian_mobile.glb 或明确配置的 FBX。导入生成的 .godot 文件不作为手工编辑对象。Godot 4.6 已有内置 FBX 导入支持；是否转 GLB 是资产交付选择，并非必须额外安装 FBX 转换程序。[官方格式说明](https://docs.godotengine.org/en/4.6/tutorials/assets_pipeline/importing_3d_scenes/available_formats.html)

自动生成 LOD 不能替代近景模型的减面、绑定和面部制作，尤其本游戏大部分时间都在近距离显示主角。

### 7.2 必须交付的动画

| 动作标识 | 类型 / 参考时长 | 内容和验收 |
|---|---|---|
| idle_a、idle_b | 循环，3–6 秒 | 呼吸、重心小变化；首尾自然衔接 |
| greet | 单次，约 1.5 秒 | 看向玩家并招手 |
| listen_enter | 单次，0.2–0.35 秒 | 头部侧倾、手靠近耳侧、身体轻前倾 |
| listen_loop | 循环，1–2 秒 | 清晰保持倾听姿态；幅度小 |
| listen_exit | 单次，约 0.2 秒 | 平滑回到可说话姿态 |
| talk_loop | 循环 | 身体节奏自然；面部/发声部件由音频包络驱动 |
| touch_head、touch_body、touch_foot | 单次，0.4–1 秒 | 三类反馈可从动作上区分 |
| eat | 单次，1–2 秒 | 注意食物、吃下、满足；标记吃到的表现时点 |
| happy | 单次，约 1 秒 | 可用于领奖或照顾后的回应 |
| sleep_enter、sleep_loop、sleep_exit | 进入/循环/退出 | 任何时刻唤醒都有有效过渡 |
| RESET | 重置姿态 | 清理骨骼、面部和材质动画遗留状态 |

P0 至少有两种待机、完整倾听过渡、说话循环和一种触摸反馈。P1 补齐表格。面部表演应遵循已有角色设计；若采用发声灯/面屏方案，必须明显跟随声音变化并通过体验验收。

临时静态模型的整体摇动可以用于技术占位，但不能作为“已完成侧耳动画”的交付证据。

### 7.3 首版内容量

一间简洁房间、6 件装扮/摆件、3 种食物外观（基础效果可相同）、6 个任务模板、3 个空闲事件、1 个小游戏。优先制作能被玩家经常看见的内容。配色从现有模型中提取，UI 不覆盖角色特征。

音频先完成一套统一音量的短音效与一条轻音乐。现有长音轨和笑声音频需要确认用途和可发布来源后进入资源清单；按引用导出，避免把所有源音轨打进安装包。

## 8. 手机支持与性能目标

“大部分手机”转化为一个可验证的支持范围：Android 9+、ARM64、至少 3GB RAM、支持 OpenGL ES 3.0 的设备作为首版设计基线；较新的 4–6GB 手机提供更清晰画面。iOS 以 iOS 16+、A12 级别及以上设备作为首轮候选基线，取得实际设备后再确认支持清单。这些是产品目标，不是市场覆盖率结论。

建议先评估 **Compatibility** 渲染器：本项目是单角色、固定镜头、简化房间，功能需求较容易控制，Compatibility 的硬件覆盖范围更广。Mobile 渲染器适合较新硬件；不能因为名称含有 Mobile 就认为旧手机兼容更好。首个设备关卡比较两者，再冻结每个平台的发行配置。[Godot 渲染器选择](https://docs.godotengine.org/en/4.6/tutorials/rendering/renderers.html)

| 项目 | 基础档目标 | 标准档目标 |
|---|---|---|
| 帧率 | 默认 30 FPS | 默认 30 FPS；通过持续运行测试后开放 60 FPS |
| 角色三角面 | 8k–15k | 15k–30k |
| 场景可见三角面总量 | ≤60k | ≤100k |
| 总 draw call，含 UI | ≤60 | ≤80 |
| 主角主要颜色贴图 | 1024 | 2048 |
| 3D 渲染短边 | 约 540 像素 | 约 720 像素 |
| 阴影 | 小范围假投影/烘焙 | 同基础方案；额外效果单独验证 |
| 常驻进程内存 | 目标 ≤250MiB | 目标 ≤300MiB |
| 峰值进程内存 | 目标 ≤400MiB | 目标 ≤450MiB |
| 语音临时内存 | ≤16MiB，且循环使用后不持续增长 | 同基础档 |
| 可安装包体 | 初版目标 ≤120MiB，按实际发行包统计 | 同基础档 |

参数是初始预算；实际性能以 release 包、真实设备和持续运行结果为准。三角面数、draw call、贴图字节和包体大小各自衡量不同成本，不能相互代替。未压缩 RGBA8 的 4096² 贴图仅基础图像就约 64MiB，包含完整 mipmap 约 85.3MiB；当前 PNG 的磁盘大小不是运行时占用证明。

基础档采用单一简单主光、环境补光、少量材质和少量透明特效。3D 分辨率可降，文字与按钮维持清晰。特效采用短时、少量、复用节点，禁止为了一个房间引入复杂的动态全局光照。

## 9. 推荐交付顺序

| 关卡 | 核心产物 | 放行条件 |
|---|---|---|
| M0：资源与设备验证 | 模型修复路径、导出样包、声音小样、性能基线 | 至少一台较低配置 Android 能显示角色并完成录音回放 |
| M1：核心交互样片 | 待机→倾听→高音复述→待机；权限、手动模式、暂停恢复 | 真机反复互动无自我复述、缺句首、状态卡死 |
| M2：可持续玩的小版本 | 三项状态、照顾、小游戏、装扮与保存 | 零货币也能玩，重启进度正确，奖励不重复 |
| M3：内容与反馈打磨 | 完整首版内容、第一轮用户体验调整 | 玩家理解交互，愿意自主尝试重复玩法 |
| M4：发行候选 | 质量档位、真机矩阵、平台导出与发布资料 | 功能、声音、性能与生命周期验收完成 |

关键路径通常是“模型可表演化 + 真机音频流程”，应最早处理。游戏结构可用占位模型搭建，但正式表演验收必须使用实际角色。

粗略工作量以一名熟悉 Godot 的开发者加一名可支持绑定动画的技术美术为前提：M0 约 3–5 工作日，M1 约 6–10 日，M2 约 8–12 日，M3/M4 约 7–12 日；美术制作可能与部分程序任务交叉。整体按 5–8 周规划起步，并在 M0 后重估。源模型重拓扑、补面部、iOS 设备/签名条件不足都可能延长周期；自动代码生成不能替代这些交付。

## 10. 怎么确认它真的好玩

第一次完整样片找 5–8 名未参与开发的人试玩，每人约 10 分钟。记录行为和时间，不需要保存他们的语音内容。

| 观察项 | 第一轮目标 | 不达标时优先修改 |
|---|---|---|
| 能否自行完成首次模仿 | 80% 的玩家在主动打开麦克风后 60 秒内完成 | 引导、授权、音量提示和句尾判断 |
| 是否愿意再试不同声音 | 10 分钟内自主尝试至少 5 次 | 回放声音、响应速度、角色表演变化 |
| 是否看懂三项状态 | 能说明至少两项的作用和恢复方法 | 图标、文案和照顾后的反馈 |
| 是否找到短期目标 | 能主动指出想解锁的一件物品 | 奖励预览、价格、任务可达性 |
| 等待是否令人烦躁 | 无连续“它怎么没听到/还不说”的困惑 | 自动检测调参和手动模式位置 |

小规模测试用于找问题，不据此宣称已证明长期留存。首版的优先优化顺序是：声音完整可靠 → 响应及时 → 表演有趣 → 养成节奏 → 内容扩充。

执行时使用 [开发任务与验收](IMPLEMENTATION_PLAN.md) 的任务卡，每次提交一个可观察、可验证的交付物。
