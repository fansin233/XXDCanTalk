# 西小电：右侧功能入口与中央面板设计交付

版本：1.0 · 2026-10-01 · 适用 Godot 4.6.1 / 当前项目

状态：设计方案与开发任务书。本文对应本次 UI 改版，尚未在游戏中实施，也未进行手机验收。

本文替代 `SHOP_INVENTORY_TRAVEL_SPEC.md` 第 8 节中“更多入口、底部功能面板”的布局规定。商店数值、存档、事务、旅行时间、奖励及音频规则继续以原规格和现有服务为准。

## 1. 最终推荐方案

**主界面右侧放三个常驻入口：商店、背包、探险；点击后在安全区中央打开同一套面板。**

- 每个入口采用“圆角图标底 + 下方中文短标签”，可点击范围包含图标和文字。
- 主界面取消“更多”。底部第一行变为“喂食 / 玩耍 / 休息”三个等宽按钮。
- 来信、图鉴放入探险面板的二级页签：`行程 / 来信 / 图鉴`。三个主入口足以覆盖已有五个功能，不在角色旁堆五个按钮。
- 顶部星星仍可直接打开商店；喂食仍直接打开背包的食物分类。
- 设置仍在右上角；设置和功能面板互斥，并纳入统一输入及返回管理。
- 主界面优先展示角色。打开功能面板后，允许面板遮挡角色中部，背景压暗并停止角色触摸；关闭后立即回到完整主界面。
- 玩家看到的名称统一为“探险”，内部继续使用现有 `travel` 标识，避免改动存档字段与服务接口。

### 原入口到新入口的映射

| 现有入口 | 新入口 | 点击结果 |
|---|---|---|
| 更多 → 商店 | 右侧商店 / 顶部星星 | 商店商品页 |
| 更多 → 背包 | 右侧背包 | 背包全部分类 |
| 底部喂食 | 底部喂食 | 背包食物分类，保留免费基础喂食 |
| 更多 → 旅行 | 右侧探险 | 探险行程页 |
| 更多 → 收件箱 | 探险 → 来信 | 来信列表 |
| 更多 → 名片图鉴 | 探险 → 图鉴 | 名片图鉴 |
| 右上设置 | 原位置设置 | 共用中央面板外壳的设置页 |

探险入口每次从主界面进入时固定打开行程页，不根据红点偷偷改变目标页面。来信页签同时显示角标；从系统内的“查看来信”按钮可以明确直达来信页。

## 2. 视觉方向：奶油色、淡紫色、简洁的小图标

沿用已有浅色房间和角色配色。主要控件使用不透明浅底，深色文字；主按钮使用紫色。控制面板边框、阴影与装饰的数量，让视觉注意力先落到角色和物品图上。

### 色彩与字体

| Token | 建议值 | 使用范围 |
|---|---|---|
| `surface_panel` | `#FFFAF2` | 中央面板、大底栏 |
| `surface_card` | `#FFFFFF` | 商品、背包卡片 |
| `surface_tint` | `#EEEAF8` | 图标底、未选中的次级操作 |
| `text_primary` | `#29283C` | 标题、物品名、数量 |
| `text_secondary` | `#666477` | 说明、时间、来源 |
| `accent` | `#7060C9` | 主要操作、选中态；比现有紫色略深 |
| `accent_text` | `#FFFFFF` | 紫色按钮文字 |
| `star_surface` / `star_text` | `#FFF0C8` / `#765015` | 星星价格与余额 |
| `notice` | `#B83E58` | 未领取数量、需处理提示 |
| `success` | `#3D745B` | 成功反馈文字 |
| `scrim` | `#242638`，透明度 0.32 | 全屏遮罩 |

以下为 720 设计宽度下的字号：面板标题 36，物品名/正文 28，操作标签 28，辅助文字 24，角标 22。仅标题使用较高字重，数值使用等宽数字。不要使用细体、文字描边或发光。

手机参考宽度 360 时，上述字号大致对应 18 / 14 / 12 的可见尺寸；实际屏幕缩放、字体放大需要单独验收，不能把设计像素直接当作 dp。正文与按钮文案对比度目标至少 4.5:1，图标和焦点标记至少 3:1。

统一使用当前可覆盖中文的字体资源；如需换字体，应选可随游戏分发的字体并保留许可证。数字、中文和图标分开绘制，避免系统 emoji、生僻字符替代图标产生设备差异。

### 图标资产要求

| 类别 | 图形意象 | 交付要求 |
|---|---|---|
| 商店 | 小店铺棚顶 / 购物袋 | 图形在 48×48 画布内，四周至少 4 留白 |
| 背包 | 有翻盖的小背包 | 和商店图标保持相同视觉重量 |
| 探险 | 指南针 | 保持与“玩耍”的跑步/游戏图标区分 |
| 来信 / 图鉴 | 信封 / 相片册 | 24×24 或 32×32 辅助图标 |
| 通用 | 星星、关闭、返回、加、减、勾、锁 | 单一套风格，圆角线条 |
| 商品 | 饭团、牛奶、曲奇、便当、饮料、小册、卡片、手账 | 独立透明底图，128×128 起；不能只显示一个汉字 |
| 纪念品 | 徽章、小票、书签、圆石、碎片、贝壳 | 可暂用统一带标识占位图，名称必须真实 |

导航图标推荐自行绘制简洁 SVG，48 画布约 2.5–3 的线宽，圆端点、圆连接，最多两种颜色。允许先用带明确商用许可的同一套图标替代并保留授权文件。示意里的通用线性图标仅表达位置与功能，不作为最终商品美术验收标准。

圆角统一：面板 28、卡片 20、按钮 18、图标底 22；面板最多一层柔和阴影，其余主要通过留白和底色区分。角色模型、材质、骨骼和房间曝光不随这次改版变动。

## 3. 主界面布局规格

### 3.1 设计坐标与区域

工程现有参考尺寸为 **720×1280**，采用 `canvas_items` 拉伸与 `expand`。以下坐标是美术标注参考；实现用安全区、锚点和容器计算，不能复制为所有机型固定坐标。

| 区域 | 无系统遮挡的参考范围 | 自适应原则 |
|---|---|---|
| 顶部资料/星星/设置 | x=24，y=24，宽=672，高约 104 | 顶部贴安全区，右上设置与星星都有独立触摸范围 |
| 三维状态条 | y≈144–200 | 仍为饱腹/电量/心情，不增加第二套仪表 |
| 角色展示区 | y≈228–800 | 优先给头、手、脚留空间；实际范围由动画投影确认 |
| 右侧功能列 | x≈584，y≈280，宽=112，高=376 | 右边距安全区 24，三项各 112 高，项间 20 |
| 临时消息 | x≈56，y≈808，宽≈608，高≥48 | 位于底栏上方；无消息时连背景一起隐藏 |
| 底部操作区 | x≈24，y≈872，宽≈672，高≈384 | 底边始终距底部安全边界至少 24 |

右侧功能列位于状态条下方、底栏上方。建议以这段空间为锚定区域，视觉中心略高于中线。长屏增加角色周围留白，功能列不拉伸，也不贴近顶部状态栏；短屏先减小装饰间距，再调整排版，触摸范围不得随意缩小。

### 3.2 右侧入口组件

一个 `FeatureRailButton` 包含：

1. 完整 112×112 的 Button 点击区。
2. 上部约 76×72 的浅色图标底，图标显示尺寸 48–56。
3. 下方 24 号文字，图标和文字之间约 4。
4. 右上角一个角标；角标不作为另一个小点击目标。

功能列不画一整根大底板，各入口独立排列。点击区始终覆盖标签。正常态浅底；按下时轻微变深并缩至 0.96；没有桌面悬浮时也能理解用途。打开面板期间底下功能列只作为背景，不允许穿透点击换页。

标签固定使用“商店 / 背包 / 探险”，不显示很长的功能描述。点击不依赖长按或二级气泡。

### 3.3 角色与入口的关系

- 默认先保持现有相机和模型摆位，测量待机、跳跃、倾听、摸头、捧腹大笑的最大屏幕投影范围。
- 右侧入口的左边缘与角色常态可见轮廓目标间隔至少 16–24 设计单位。初步角色保护范围可参考 x=96–560，但它是待实机修正的设计目标，不是已经测得的模型边界。
- 有重叠时，先在允许的纵向区域内移动功能列；确需调整构图时再小幅调整相机 framing，并同时核对地面接触和触摸映射。不能靠修改骨骼姿势给按钮让位。
- 主界面的大面积触摸区需要排除功能按钮、顶部和底部控件；不能只提高图标的 `z_index` 就认为不会触发角色动作。
- 所有触摸区对齐新角色位置；尤其检查之前出现过的“身体点击无反应”。

### 3.4 底栏

第一行由四列变三列，释放的宽度均分给喂食、玩耍、休息。不要新增占据“更多”位置的第四个入口。按住说话、音量指示、自动聆听和麦克风状态继续保留；**麦克风状态文字位于底栏最下方**。

一般操作点击区优先至少 96×96 设计单位；右侧入口为 112×112。基于 360 宽参考设备对应约 48/56 的可见尺寸，验收时应确认最小触摸区域约 44 dp 或更大；320 宽设备如不足，放大到约 104 设计单位并让底栏自然增高，不能仅缩小整套 UI。

收起面板后，不自动触发喂食、触摸或录音。打开面板前尚未完成的按住说话操作要取消，不能把之后的手指松开识别为一次有效录音提交。

## 4. 中央面板公共规范

### 4.1 结构与尺寸

所有商店、背包、探险、设置使用同一个 `OverlayHost`。结构固定为：

```text
全屏遮罩（输入拦截）
  安全区内居中的面板
    标题栏：返回〔详情时〕 / 图标 + 标题 / 星星〔需要时〕 / 关闭
    页签或分类栏
    反馈提示〔有结果时才出现，或预留固定反馈行〕
    可滚动内容
    固定操作栏〔当前页面有主要操作时〕
```

- 默认宽度 `min(656, 安全区宽度 - 48)`，高度 `min(960, 安全区高度 - 48)`；位置取**安全区中心**。720×1280 且无遮挡时约为 `(32,160,656,960)`。
- 面板内边距 24；公共间距 12/16/24；标题栏约 96，页签约 88，主要操作按钮约 96 高。关闭按钮使用完整至少 96×96 点击区，图形本身可为 36。
- 标题、页签、操作栏不随列表滚走；只有中间内容区域垂直滚动。
- 初版同一功能的详情在原面板内替换内容，保持外框大小。禁止在商店窗口上再叠一层更小的购买窗口。
- 商店根页没有选中商品时不强行保留空操作栏。详情页显示购买/使用；来信列表显示领取全部。
- 反馈显示在面板内部，不放到被遮住的主界面消息区；不会覆盖购买/领取按钮。
- 字体放大时优先两行物品名、卡片增高、减少列数；短屏优先让内容滚动，关闭和主要操作仍可见。极端高度不足时，把非关键说明与分类放入内容区。

### 4.2 交互规则

| 操作 | 规则 |
|---|---|
| 点击右侧入口 | 打开对应根页，清空上一次详情；恢复该功能最近的分类与列表滚动位置（喂食和探险固定入口规则除外） |
| 点击物品 | 进入该物品详情；仅浏览不消耗道具 |
| 详情左上返回 / Android 返回 | 返回父页，恢复分类、选中项和滚动位置 |
| 根页 Android 返回 | 关闭面板，回到主界面 |
| 右上关闭 | 关闭整套功能面板 |
| 点击面板外遮罩 | 根页关闭；详情页返回父页；提交进行中不响应关闭 |
| 面板上划动 | 只滚动内容，不触发角色或底栏 |
| 关闭动画进行中 | 继续拦截输入；动画结束后再恢复主界面触摸 |
| 多次快速点击入口 | 只打开一个面板实例，不叠遮罩，不重复获取令牌 |
| 从背包“用于出行”跳转 | 在同一 Host 内进入探险准备页，返回可回到来源详情；尚未点击出发不消耗便当 |

关闭不会取消已完成的购买/领取。当前服务是同步事务；UI 也按未来可能出现异步结果设计：控制器持有请求 ID，视图释放后不写入已失效节点，余额和背包从服务快照恢复。

### 4.3 动效

| 场景 | 动效 | 时间 |
|---|---|---|
| 打开 | 遮罩 0→0.32；面板透明度 0→1，比例 0.96→1 | 180–220 ms，缓出 |
| 关闭 | 面板 1→0.98 并淡出；遮罩淡出 | 120–160 ms |
| 页签/详情切换 | 内容短淡入；外框不跳高、不转场飞行 | 100–140 ms |
| 点击按钮 | 压暗 + 轻微缩放后恢复 | 60–100 ms |
| 新信件 | 角标出现一次；主界面合并提示 | 不循环闪烁 |

不做实时背景模糊、毛玻璃、反复弹跳和粒子雨。Tween 作用于容器外的动画包装 Control，不与 Container 的布局管理争夺子节点位置。连续开关时先结束旧 Tween，再建立新状态。后台恢复直接落在稳定布局。减弱动画模式只保留极短淡入淡出。

## 5. 各功能页面

### 5.1 星星商店

**根页：** 标题 + 星星余额 → 分类 `全部 / 食物 / 恢复 / 成长` → 两列商品卡片。

- 656 宽面板、24 内边距、16 列间距时，卡片约 296 宽，建议高 232–264。
- 每卡只显示：物品图、名称、主要效果简述、星星价格；持有数可用一行小字。整卡点击进入详情。
- 价格来自 Catalog，禁止把静态图中的数字写成程序常量。
- 两列为默认。内容宽度不足以容纳两张可读卡片时改一列，不缩小正文。初版不添加搜索、促销倒计时或随机上架。
- 余额不足仍可浏览；详情购买按钮不可执行，并明确显示“还差 X 星”，不要只有灰色按钮没有原因。

**详情：** 图 + 名称 → 完整效果 → 持有数量 → 数量 `− / 1 / +` → 底部“购买 · X 星”。数量初始 1，沿用服务上限，按钮边界校验；提交后进入忙碌态。

成功：显示“已放入背包：丁香饭团 ×1”，更新余额/持有量，停留详情；提供次级“去背包”入口。失败：显示服务返回原因，保持所选物品与数量。事务失败不得先播放已买到的反馈。

### 5.2 背包

**根页：** 标题 → 分类 `全部 / 食物 / 恢复 / 成长 / 纪念` → 物品网格。

- 分类使用自适应两行或轻量水平滚动条；不能把五个标签硬压成过小按钮。若水平滚动，保留下一项部分可见的提示，且支持触摸拖动。
- 默认两列，物品图、名称、右下数量 `×N`；点击只进入详情，不直接消费。数量 0 的物品从普通列表移除，详情页可以保留“已用完”状态。
- 使用详情显示服务计算的**实际增量**；例如饱腹临近上限时显示 `饱腹 +8（最多 +25）`，不让名义数值误导玩家。
- 主要操作：“使用 1 个”。睡眠、冷却、已满等限制以现有服务规则为准；给出明确原因。
- 纪念品只有来源/说明，不出现“使用”。旧存档未知道具显示通用图 + 原 ID/保留数量，不报错也不允许消费。
- 食物分类保留“免费基础喂食”独立次级按钮；空背包提供“去商店”，不能把免费入口一起隐藏。
- 便当详情同时提供“用于探险”次级操作，跳到准备页并选中便当；该操作只预选，不扣库存。

初版每次使用 1 件，不引入批量使用新规则。使用结果留在详情展示；数量耗尽时禁用主按钮，返回列表后移除该卡片。

### 5.3 探险：行程 / 来信 / 图鉴

标题显示“西小电的探险”。页签分别配指南针、信封、相片册小图标。右侧主入口和来信页签均可显示通知角标。

**行程页状态：**

| 状态 | 内容 | 主要操作 |
|---|---|---|
| 尚未体验引导 | 可跳过的校门散步引导卡 + 常规路线 | “校门散步”或选择常规路线 |
| 空闲 / 准备 | 三条路线选择卡 + 预计时长范围 + 便当选择 | “出发” |
| 在途 | 地点占位插画 + 旅程进度 + 已寄回张数 + 来信入口 | “查看来信” |
| 已归来、待整理 | 归来文案 + 本趟摘要 + 来信入口 | “收好行李” |

在途只是展示旅程数据；家中角色仍可互动。关闭面板后恢复家中语音与触摸。预计时长使用配置范围；在途可显示大致剩余时间，不需要持续倒数秒。打开/恢复页面立即刷新，之后最多每秒更新当前可见数值。

保留现有出行时消耗便当、离线结算、不能途中取消与“收好行李不重复发奖励”等规则。返回按钮离开准备页不会自动出发。点击“出发”就是明确提交，不再套一个冗余确认弹窗。

**来信：** 缩略图 + 地点 + 一段摘要 + 状态（未读/附件待领取/已领取）。点开大图与全文，底部“收下附件”；只读信不自动领取。列表底部“领取全部”，没有待领取时显示状态。继续使用当前分页上限 20，分页按钮也在固定操作区。

**图鉴：** 两列名片缩略图，已收集显示真实占位图与名字，未收集用统一封套；数量与 6/12/18 的现有收集奖励状态清楚呈现。不得在本次 UI 改版时另加自动发奖途径。详情显示地点、稀有度、正文；正式图片后续替换现有占位 SVG。

### 5.4 红点与反馈

- 数字角标 = `MailboxService.pending_count()`，表示有附件可领取；大于 99 显示 `99+`，原值用于详情。
- 没有待领取附件但有未读信，显示小圆点；都没有则隐藏。读取信件不会清掉仍待领取的数字。
- 图鉴可领取奖励若当前业务需要手动领取，应由其真实领取状态决定图鉴页签角标；现有自动到账规则不另造“待领取”。
- “旅途中”用安静的状态小点或图标变化表达，不与奖励红点混用；不得持续呼吸或闪烁。
- 主界面有多封同时到达时只显示一次合并消息。消息结束连同底色消失；不留下空白框。
- 所有按钮的点击音沿用 SFX 设置，不增加大音量反馈。页面不会自动播语音或盖过角色复述。

### 6.2 安全区与缩放

1. HUD 与 Overlay 共用一个 `SafeAreaLayout`，统一输出 UI 根坐标中的 `safe_rect`。
2. 手机上读 `DisplayServer.get_display_safe_area()`；它给出可放交互控件的未遮挡区域。桌面与编辑器预览使用自己的视口矩形，不把桌面任务栏尺寸直接当成手机留边。依据：[Godot 4.6 DisplayServer](https://docs.godotengine.org/en/4.6/classes/class_displayserver.html#class-displayserver-method-get-display-safe-area)。
3. 将屏幕矩形四角通过 UI 根 `get_screen_transform().affine_inverse()` 转为根局部坐标，再取包围矩形并与根矩形求交；坐标来源必须一致，不再另外重复减窗口位置。该方法包含屏幕/窗口变换；嵌入编辑器预览走完整视口回退。依据：[Godot 4.6 CanvasItem](https://docs.godotengine.org/en/4.6/classes/class_canvasitem.html#class-canvasitem-method-get-screen-transform)。
4. 读到空/无效安全区时采用视口内的保守边距并记录诊断。旋转、窗口大小变化、应用恢复后重新计算；不每帧创建布局。
5. 控件在换算后的四边内布局：顶部避刘海，右侧入口避曲面/边缘手势，底栏和面板底部避导航键。遮罩和装饰背景始终覆盖整个视口。
6. 沿用项目的 stretch 设置，逐步移除 HUD 与旧 FeatureOverlay 各自的固定 `_design.scale`。不要同时叠加项目拉伸与两套手动 720×1280 缩放；过渡期必须明确只有一处进行坐标转换。

上面的转换是主视口 UI 根方案。若以后加入 SubViewport、不同 CanvasLayer transform 或多窗口，重新确认坐标链，不能直接复制比例公式。

### 6.3 输入、返回与语音

- 装饰 Label/TextureRect 设置 `MOUSE_FILTER_IGNORE`，按钮和遮罩设置 `STOP`。`STOP` 管理 GUI 事件传播，但不代替全局输入状态判断；若角色使用 `_input`，必须主动检查面板是否开启。依据：[Godot Control 输入过滤](https://docs.godotengine.org/en/4.6/classes/class_control.html#enum-control-mousefilter)。
- 可使用同一根全屏 Control 下的树顺序组织输入层，不依赖单纯 `z_index`。触摸开始归属某按钮后，结束事件不能再派发到角色；避免触屏事件与模拟鼠标事件重复提交。
- 同时覆盖桌面 `ui_cancel` 和 Android 系统返回事件。禁用 `SceneTree.quit_on_go_back` 的自动退出后，由统一路由处理系统返回；根主界面需保留明确退出流程，不能吞掉全部返回操作。依据：[Godot SceneTree](https://docs.godotengine.org/en/4.6/classes/class_scenetree.html#class-scenetree-property-quit-on-go-back)。
- Host 从关闭进入开启时获取 **一个** `VoiceService.acquire_suspend("overlay")` 令牌；切页、详情返回、同 Host 跳转不释放。完全关闭且退场结束时才释放。
- 现有 Main 持有 `_feature_voice_token`。迁移可以先由 Main 继续唯一持有，Host 只发 opened/closed；不要 Main 和 Host 各取一次后只释放一次。
- 设置从原 HUD 独立覆盖层迁入 Host 后，移除旧设置令牌分支；迁移完成前以“先获取目标令牌，再释放来源令牌”防止中间一帧误恢复录音。
- 不调用全局 `SceneTree.paused` 来打开商店；后台结算与必要状态更新继续工作。音频暂停原因、自动聆听开关、跑酷令牌、笑声令牌继续独立。
- Host 关闭或释放时释放自己持有的令牌、停止 Tween、断开页面信号。应用在后台时由后台令牌继续阻止麦克风恢复。

### 6.4 页面路由与既有接口

建议新增的 UI 路由接口如下，**它们是设计接口，当前尚未存在**：

```gdscript
# Route 只保存 UI 状态，不写入 GameStore 存档。
open_feature(page: StringName, params: Dictionary = {})
push_detail(kind: StringName, id: String)
pop_page()
close_all()
is_open() -> bool
```

根路径 `shop`、`inventory`、`travel`；`mailbox`/`album` 路由映射到 `travel` 的相应页签；`food` 映射到 `inventory`，参数 `category="food"`。来自背包的便当跳转显式保存来源 Route。

| UI 行为 | 继续使用的命令/数据 |
|---|---|
| 买商品 | `command_requested("buy", {item_id, quantity, catalog_version, request_id})` |
| 使用道具 | `command_requested("use", {item_id})`，控制器生成并持有 request_id |
| 免费喂食 | `free_feed` |
| 引导/出发/整理 | `tutorial` / `depart` / `ack_return` |
| 读信/领取 | `mark_read` / `claim` / `claim_all` |
| 余额/库存/旅程/图鉴 | `GameServices.store.get_snapshot()` 及现有只读服务方法 |
| 角标 | `mailbox.pending_count()` / `unread_count()` |

UI 只传 ID、数量、选择与请求标识，不传可信总价/奖励。点击购买、使用、出发、领取后立即禁用相关提交入口，成功或明确失败后恢复；存档错误保留数据与错误说明，重试同一操作复用 request_id。

每个可见页面保留自己的 `category / selected_id / scroll_offset`。切换页面保存，返回后等待布局完成再恢复滚动。1 Hz 状态刷新只改相应 Label/ProgressBar/Badge，不重建整页，避免滚动跳顶和卡片闪烁。

物品贴图按稳定 ID 或 `art_key` 映射到 Resource，不把文件路径存入游戏存档。找不到图片时使用统一占位图；导出检查 JSON 与图片均在资源包内。
