商店、背包和独立出行的后续实施请使用 [扩展开发规格](SHOP_INVENTORY_TRAVEL_SPEC.md) 第 15–17 节；其中的数据迁移、模块接口和任务依赖针对现有 1.0.1，本文保留为原版开发记录。

版本：v1.0 · 日期：2026-09-29

产品定义见 [PROJECT_PLAN.md](PROJECT_PLAN.md)，实现约束见 [TECHNICAL_SPEC.md](TECHNICAL_SPEC.md)。本文件是可以交给开发者或执行模型的工作清单；当前代码进度和验收状态见 [BUILD_STATUS.md](BUILD_STATUS.md)。

## 1. 开工规则

1. 实际项目根目录为 E:/作品/XXD/XXDCanTalk/会说话的西小电，当前资源文件夹拼写为 Assests。
2. 从 M0 开始，每项任务提交清晰的文件变更、运行入口和验收证据。已有资源盘点见 model_audit.json，模型变化后才重新盘点。
3. 每次任务读取对应规格，先满足依赖再进入实现；必要的占位组件必须显式标记，不能作为美术或真机功能完成的证据。
4. 游戏数值、语音参数、动作映射放配置资源；不得在多个脚本中分别硬编码同一规则。
5. 交付报告区分“桌面验证”“Android 真机验证”“iOS 真机验证”。缺少设备时记录未验证项，不能用编辑器帧率替代手机结果。
6. 修改原始模型时产出派生文件；运行代码使用项目相对资源路径，不能依赖当前机器上的 E: 盘路径。
7. 状态机和资源交易各有唯一写入模块；语音、动画、UI 分别按既定接口协作。
8. 版本管理初始化、仓库范围和资源存储方式在 M0 固定；仅提交项目源码、必要导入配置和资源，排除 .godot、构建产物、签名密钥。

每个任务的交付报告统一包含：任务 ID、具体变更、启动方法、测试环境、已通过项、未通过/未验证项、遗留依赖。遇到设备或美术依赖，继续推进可独立完成的工作，并明确阻塞项。

## 5. 功能验收矩阵

“必过”表示发行候选必须有证据；“条件必过”表示宣称支持该平台或路由时必须通过。

| 编号 | 场景 | 预期 | 门槛 |

| V02 | 以轻辅音开头、很短的话、笑声、较长句子 | 不吞句首；短句规则可解释；无重复帧造成的颤音 | 必过 |
| V03 | 说话中停顿300–500ms后继续 | 不被切成两段；达到句尾阈值后才结束 | 必过 |
| V04 | 连续讲话超过12秒 | 停止本段并回放已录内容；内存不无限增加 | 必过 |

| V06 | 开扬声器完成20轮模仿，用户随后保持安静 | 不自动复述自己的声音，也不累计下一段声音 | 必过 |

| V09 | 初次拒绝、再次开启、系统撤销权限 | 无崩溃、无授权死循环；静音玩法正常 | 必过 |
| V10 | 采集无帧、丢帧或路由改变 | 明确恢复流程，不播放坏数据、不无限等待 | 必过 |
| V11 | 快速重复点击开关和切换AUTO/HOLD | 始终只有一个输入实例；会话不会交叉 | 必过 |
| V12 | 有线/蓝牙耳机、路由切换 | 输入源、回放位置与恢复正确；记录延迟差异 | 条件必过 |
| L01 | 录音/处理/回放中分别锁屏、切应用、来电 | 停输入与回放；返回后可重新进行下一句 | 必过 |
| L02 | 进入小游戏、休息、设置及返回 | 有清晰的暂停与恢复规则，无后台隐藏录音 | 必过 |
| A01 | 重导入角色资源 | 材质、动画映射、装饰挂点和场景引用有效 | 必过 |
| A02 | 倾听转发声、发声取消、摸头后立刻说话 | 无卡姿态、叠加播放或重置跳帧 | 必过 |
| U01 | 16:9、19.5:9、20:9及平板窗口 | 安全区正确、文字清晰、角色不被主要控件截断 | 必过 |
| U02 | 多指触摸、拖拽物品、点菜单 | 只由拥有该触摸的控件处理，不误点角色 | 必过 |
| S01 | 完成购买/奖励后立刻重启 | 所有相关状态一致；不丢钱、不重复发奖 | 必过 |
| S02 | 保存过程中杀进程、损坏主文件、模拟写失败 | 能恢复到有效版本；错误可见 | 必过 |
| S03 | 离线8小时以上、时间倒退/前跳、反复切后台 | 衰减受限，不重复结算；每日奖励有去重 | 必过 |
| S04 | 老 schema 存档 | 可迁移或明确恢复，不静默清除进度 | 有旧版本后必过 |
| G01 | 零货币、低状态、关闭麦克风 | 照顾和小游戏可持续游玩 | 必过 |
| G02 | 小游戏重复结束回调/领奖连点 | 同一 run_id 只结算一次 | 必过 |

自动化优先覆盖确定性行为：检测状态的样本输入与边界、会话取消、交易去重、存档恢复和时间计算。音色好不好听、动作是否自然、手机授权弹窗和扬声器回录必须真机/人工验证。

音频测试样本由开发者自愿录制或使用明确可测试的素材；样本集应覆盖不同音高、语速、距离和噪声，至少20段清洁人声、10段短噪声/背景声。不把真实玩家录音默认上传作为测试数据。

## 6. 量化体验与性能验收

以下数字是拟定目标。测试开始前固定包版本、配置与设备，不通过挑最好的一次结果验收。

| 指标 | 测法 | 第一版放行目标 |
|---|---|---|
| 触摸可见反馈 | 输入事件到首个反馈帧 | P95 ≤100ms |
| 自动倾听提示 | 持续过阈值开始到可见提示 | P95 ≤250ms，包含起听防抖 |
| 句尾到复述声音 | 最后一个有效发声到扬声器首个回放声 | 内置扬声器场景 P95 ≤1.4秒，包含句尾等待 |
| 录音后整理 | PROCESSING 进入到提交播放 | 最低设备 P95 ≤150ms |
| 安静环境完整录入 | 固定清洁样本/人工说话集，固定距离与音量 | 至少95%无需重试且无明显句首/句尾截断；失败样本保留原因 |
| 安静待机误触发 | 固定普通安静房间，开自动模式观察10分钟 | ≤1次；电视/人群场景另列结果，不冒充安静环境 |
| 自我复述 | 扬声器常用音量及高音量分别20轮 | 无自我复述循环 |
| 基础档稳定帧率 | release、20分钟互动混合场景 | 平均≥29FPS，帧时间P95≤40ms，无持续性长卡顿 |
| 可选60FPS | 对应机型release、20分钟 | 平均≥55FPS且P95≤20ms，否则只开放30FPS |
| 稳定内存 | 预热5轮后再做100轮录音/回放 | 不持续增长；结束后稳定值相对预热后增长≤20MiB，超出必须解释与处理 |
| 冷启动到可互动 | 至少5次冷启动，release，独立记录系统差异 | 基础设备目标≤5秒；超过需报告瓶颈并优化 |
| 复合恢复 | 多次切后台/锁屏/小游戏/耳机变化后再说话 | 无崩溃、卡死、静默失效或重复播放器 |

持续运行同时记录机身发热、明显降频和电量变化，固定亮度及帧率以便比较。首先解决导致卡顿或音频爆音的峰值，不能只报平均帧率。

## 7. 设备与平台矩阵

设备型号在 M0 根据实际可取得的设备填写并冻结。以下描述是选机维度，不能用桌面模拟器替代。

| 档位 | 必须覆盖的特征 | 优先检查 |
|---|---|---|
| Android 基础档 A | 3GB左右、较老 Adreno/骁龙设备、Android9或附近版本 | GLES兼容、内存、音频处理耗时 |
| Android 基础档 B | 3–4GB、Mali/联发科或同类GPU设备 | 驱动差异、材质、输入稳定性 |
| Android 中档 A/B | 两个不同厂商系统、4–6GB、不同Android代际 | 权限、音频焦点、后台恢复 |
| Android 较新设备 | 高刷新率、高分辨率及新系统版本 | 耗电、60FPS开关、长屏布局 |
| Android 补充设备 | 与上述不同的GPU或音频路由行为 | 降低只适配单一厂商的风险 |
| iOS 基础档 | 拟定最低支持范围附近的A12级设备 | 录音会话、渲染、发热和恢复 |
| iOS 较新设备 | 新系统、不同屏幕/刘海或灵动岛尺寸 | 安全区、路由切换和权限行为 |

Android 首发至少完成6台不同特征的实机记录；iOS 声明正式支持前至少完成基础和较新两档，产品覆盖范围越广越需要扩展样本。每份报告记录机型、系统、RAM、GPU、音频路由、分辨率、渲染器、画质、构建标识及结果。

商店的最低/目标 SDK、签名、包格式和其他发行要求，在真正准备发布时核对相应渠道的最新官方规则。工程跑通、debug APK 可安装、release 可运行、商店可发布是分别需要完成的关卡。
